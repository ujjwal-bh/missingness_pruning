# Candidate predictor cleaning and feature construction

Status: prepared, not yet executed against PostgreSQL. The core feature table is a candidate for validation, not a frozen research model input. No model is trained. GCS/treatment harmonization remains in progress.

The researcher supplied source unit and timestamp profiles. No event or availability timestamps were missing among the reported mapped numeric sources. Entry-before-event timestamps occur and are handled conservatively using the later of event and storetime, without editing either raw timestamp. Both must be known and through the landmark. This is a documented data-availability bound, not proof of perfect chart-clock accuracy.

Clear artifacts occur in vitals and lactate, including million-scale values. Apply artifact screens to observations, not patient rows. Retain all cohort patients, missing predictor values and older valid available observations when a later observation is invalid. Do not replace missing values from future measurements or revise historical values using future entry timestamps.

Vital bounds are adapted from the MIT-LCP vitalsign concept: heart rate >0 and <300; systolic BP >0 and <400; diastolic/mean BP >0 and <300; respiratory rate >0 and <70; saturation >0 and <=100. Convert Fahrenheit to Celsius, then apply the shared Celsius bound >10 and <50 across sources. The common converted-temperature bound is an adaptation rather than a verbatim copy of the source Fahrenheit rule. These are operational artifact screens, not normal ranges or universal physiological limits.

Chemistry safety screens use positive values, with published broad upper bounds for albumin (10), BUN (300), creatinine (150), sodium (200) and potassium (30) in the specified target units. Other numeric labs use conservative broad upper guards rather than discarding severe abnormalities based on this audit's maxima. Hematocrit cannot exceed 100 percent. Nonnegative bilirubin, lactate and WBC can include reported zero values; this is an explicitly documented adaptation. No empirical cutoffs have been tuned using mortality or model performance. Borderline extreme lab observations still require scrutiny in later feature-distribution checks.

MIMIC sodium, potassium, chloride and bicarbonate use monovalent mEq/L, numerically compatible with mmol/L for these mapped analytes. Count-unit aliases K/uL, 10^3/uL and 10^9/L refer to the same scaled count. Unit acceptance is analyte-specific. Unknown units reject an observation from candidate features and are counted; raw data stay intact. eICU system/interface unit disagreements must be resolved before applying the equivalent extractor, especially for ionized calcium, which is not in the current core set.

07_build_mimic_core_candidate_features.sql creates core_features_candidate_v1 (26 core concepts plus linkage/outcome metadata) and core_observation_qc_candidate_v1. Duplicate rows at identical variable/event/availability/source are averaged before selecting the latest valid value. For equal measurement times, arterial BP takes priority; later availability breaks remaining ties without exceeding the landmark. IDs break otherwise identical source ties deterministically. The script preserves cohort row/outcome counts and asserts no post-landmark measurement or availability time is used.

The final reports include candidate patient/death counts, observation rejection counts (which can overlap), feature coverage by landmark and stored temperature-label bytes. The scripts do not delete/rewrite source observations or change cohort views. They refuse to overwrite an existing candidate table. Run the entire file in pgAdmin against landmark_research; it may use temporary disk space and run for some time.
